The problem in one picture

Decision. Which depots to open (at most p), and which customers each vehicle serves in which order.

Objective. Minimise total latency, the sum of customer arrival times.

Constraints. Vehicle capacity Q; each customer is visited once.

1

Choose an instance

Choose a built-in benchmark or upload your own instance file. Built-in instances carry their best known solution (BKS), which the gap uses.

Using your own data? What the file should look like

Use one plain-text file with the extension .inst. It has three parts: a header with the problem settings, the candidate depots and the customers. Distances are computed from the coordinates (Euclidean, not rounded), so no distance matrix is needed. Routes are open: a vehicle does not return to its depot.

About this solver

    
How it runs. The solver is written in C++ and compiled to WebAssembly, so it runs entirely in your browser; your instances and settings are never sent to a server. The page only reports two anonymous counts (page opened, run started) to GoatCounter, an analytics service that does not track personal data. The same sources build the command-line binaries, and results are reproducible for a given seed on the same version.

    
Gap. Gap to BKS is 100 × (cost − BKS) / BKS, using the best known solution in the instance file. Costs are total latency (the sum of customer arrival times).

    
Estimated time. Estimates come from a fitted model on benchmark runs and are only indicative (roughly ±50 %); actual time depends on your device.

    
For the full model, the operator definitions and the literature behind each heuristic, see the Learn page.
